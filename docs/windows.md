# Запуск бота на своём компьютере (Windows)

Инструкция для случая «бот живёт на моём ПК, а не на сервере». Сервер нужен только
ради круглосуточной работы и HTTPS для мини-приложения — сам бот прекрасно работает
на домашнем компьютере.

Что важно понять сразу:

- бот доступен в Telegram, **только пока компьютер включён, не спит и есть интернет**;
- пропущенные за это время сообщения Telegram хранит **24 часа** — включаешь ПК утром,
  бот догоняет вечерние записи, но то, что отправил позавчера, уже потеряно;
- внутри Telegram кнопка «Открыть дневник» требует HTTPS-адрес, поэтому мини-приложение
  на ПК без домена и туннеля не заработает (см. раздел 9). Бот от этого не зависит.

Зависимостей у проекта нет: нужен только Python, `pip install` не требуется.

В примерах ниже папка проекта — `C:\kkal`. Если ты скопировал проект в другое место
(например, `C:\kkalBot\botKkal`), подставляй свой путь: всё остальное не меняется.

## 1. Перенеси проект из OneDrive

Сейчас проект лежит в `C:\Users\2004r\OneDrive\Desktop\Roben\botKkal`. Для постоянной
работы это неудачное место: база SQLite в режиме WAL держит рядом файлы `kkal.db-wal`
и `kkal.db-shm`, а OneDrive синхронизирует и блокирует их в самый неподходящий момент.
Итог — конфликты синхронизации и риск битой базы.

Сделай копию в обычную папку, например `C:\kkal`:

```powershell
# 1) остановить бота, если он где-то запущен, и только потом копировать базу

# 2) свежая копия кода из GitHub (без мусора и без лишних папок)
git clone https://github.com/Roby3hek/botKkal.git C:\kkal

# 3) свой конфиг с токеном (в git его нет и не должно быть)
Copy-Item "C:\Users\2004r\OneDrive\Desktop\Roben\botKkal\config.json" C:\kkal\

# 4) существующая база с записями и блюдами — вместе с -wal и -shm
New-Item -ItemType Directory C:\kkal\data -Force | Out-Null
Copy-Item "C:\Users\2004r\OneDrive\Desktop\Roben\botKkal\data\kkal.db*" C:\kkal\data\
```

Если хочешь начать с чистой базы — шаг 4 пропусти, она создастся сама.

Дальше все команды — из `C:\kkal`.

## 2. Проверь Python

На этом компьютере уже стоит Python 3.13.5:

```powershell
python --version
py --version
```

Должно ответить `Python 3.13.5`. Если Python нет — поставь с [python.org](https://www.python.org/downloads/),
обязательно с галочкой **Add python.exe to PATH**, и открой новое окно терминала.

## 3. Конфиг

Если `config.json` уже скопирован — проверь, что внутри твой токен и владелец:

```json
{
  "token": "123456789:AAH...",
  "owner_id": 123456789,
  "utc_offset": 4,
  "db": "data/kkal.db"
}
```

`utc_offset` — часы от UTC: Саратов `4`, Москва `3`. Токен — это пароль от бота,
в репозиторий он не попадает.

Раздел `"webapp"` нужен только для мини-приложения внутри Telegram — про него в разделе 9.
Без него бот работает как обычно, а `/app` честно отвечает «мини-приложение пока не настроено».

## 4. Первый запуск

Двойной клик по **`start-bot.bat`** в папке проекта — откроется консоль и бот запустится.
Или вручную:

```powershell
cd C:\kkal
python bot.py
```

В консоли должно появиться `Бот @имя_бота запущен`. Проверь в Telegram:

1. `/start` — приветствие и меню;
2. `/id` — бот покажет твой id (сверь с `owner_id`);
3. запиши что-нибудь: `творог 200` → бот попросит граммы или посчитает;
4. `/today` — запись появилась.

Остановить: `Ctrl+C` в окне консоли (бот корректно закроет базу) или просто закрыть окно.

## 5. Автозапуск при включении ПК

### Вариант А — Планировщик заданий (рекомендую: работает без окна)

1. `Win+R` → `taskschd.msc` → Enter.
2. Справа **«Создать задачу»** (именно задачу, не «простую задачу»).
3. Вкладка **«Общие»**: имя `kkal bot`, отметь **«Выполнять только при входе пользователя»**.
4. Вкладка **«Триггеры»** → «Создать» → «Начать задачу»: **При входе в систему**,
   поставь галочку **«Отложить задачу на»** `30 секунд` (чтобы сеть успела подняться) → ОК.
5. Вкладка **«Действия»** → «Создать» → «Запуск программы»:
   - Программа: `C:\Users\2004r\AppData\Local\Programs\Python\Python313\pythonw.exe`
   - Аргументы: `bot.py`
   - Рабочая папка: `C:\kkal`
   
   `pythonw.exe` — тот же Python без чёрного окна. Лог всё равно пишется в `data\bot.log`.
6. Вкладка **«Условия»**: сними «Запускать только при питании от сети» и
   «Останавливать при переходе на питание от батареи» (иначе на ноутбуке бот не поднимется).
7. Вкладка **«Параметры»**: «Если задача уже выполняется» → **Не запускать новый экземпляр**;
   «Перезапускать при сбое» → каждые `1 минуту`, попыток `3`.
8. ОК. Затем правый клик по задаче → **«Выполнить»** и проверь, что бот ответил в Telegram.

Пароль Windows планировщик не спросит, потому что задача стартует при твоём входе.

### Вариант Б — папка «Автозагрузка» (проще, но с окном консоли)

1. `Win+R` → `shell:startup` → Enter.
2. Правый клик → «Создать» → «Ярлык» → укажи путь к `C:\kkal\start-bot.bat`.
3. Окно консоли будет висеть после входа в систему — можно свернуть.

## 6. Проверить, что бот жив, и остановить его

```powershell
Get-Process python, pythonw -ErrorAction SilentlyContinue | Select-Object Id, ProcessName, StartTime
```

Если запускал через Планировщик — останавливай там же: выбрать задачу → **«Завершить»**.

Если запускал через `start-bot.bat` — закрой окно консоли или нажми `Ctrl+C`.

Принудительно, если ничего не помогает (останавливает **все** процессы `pythonw`,
так что сначала убедись, что других нет):

```powershell
Stop-Process -Name pythonw -ErrorAction SilentlyContinue
```

## 7. Если не работает

| Что видно | Причина | Что делать |
|---|---|---|
| `409 Conflict` в логе | запущено два экземпляра бота с одним токеном | оставь один: закрой окно/заверши задачу, а также останови бота на VDS (см. ниже) |
| `Telegram отверг токен (401/404)` | токен неверный или отозван в @BotFather | вставь актуальный токен в `config.json` |
| `В config.json не указан токен` | файл не создан или пустое поле | раздел 3 |
| `Сбой связи: ...` в логе | нет интернета, VPN, прокси, антивирус | проверь браузером `https://api.telegram.org`, при необходимости добавь `python.exe` в исключения |
| бот молчит, процесс есть | скорее всего конфликт с ботом на VDS | `sudo systemctl stop kkal` на сервере или используй второго бота |
| окно `start-bot.bat` закрывается мгновенно | ошибка при старте | запусти `python bot.py` вручную и прочитай текст ошибки |
| двойной клик по `.bat` — и ничего, даже окно не мигает | файл сохранён с переводами строк LF вместо CRLF (так делает git, если нет `.gitattributes`) | обнови проект через `git pull`; правильный файл — с CRLF, проверить: `(Get-Content start-bot.bat -Raw) -match "`r`n"` |
| первый запуск упал с `[WinError 10060]` / `сеть: ...`, а второй работает | сеть или антивирус не пустили первый запрос к Telegram | просто запусти ещё раз; если повторяется — проверь `https://api.telegram.org` в браузере и исключения в антивирусе |
| `/app` отвечает «Мини-приложение пока не настроено» | в `config.json` нет `webapp.url` | раздел 9 |
| мини-приложение открылось, но пишет «Это личный бот одного человека» | открыл не владелец или домен не тот, что прописан | сверь `owner_id` через `/id`; при туннеле — новый адрес в `webapp.url` и перезапуск бота |

Логи лежат в папке `data`:

- `bot.log` — сам бот (сообщения, ошибки Telegram);
- `start.log` — отметки запуска `start-bot.bat` (видно, что файл действительно сработал);
- `web.log` — веб-сервер мини-приложения;
- `web.err.log` — только аварийный вывод Python, если сервер не поднялся.

Файлы растут медленно, но не ротируются — раз в несколько месяцев можно удалять.

**Отдельно про VDS.** Один токен = один активный бот. Если бот уже крутится на сервере,
два поллера будут отбирать друг у друга сообщения (`409`). Перед запуском на ПК останови
серверного: `sudo systemctl stop kkal` (и `sudo systemctl disable kkal`, если он больше не нужен).

## 8. Сон, ноутбук и прочее

- Спящий или выключенный ПК = бот офлайн. Параметры → Система → Питание и спящий режим:
  «Переход в спящий режим» → **Никогда** (хотя бы при питании от сети).
- Ноутбук с закрытой крышкой: «Действие при закрытии крышки» → **Ничего не делать**,
  иначе бот умрёт при первом же захлопывании.
- Перезагрузка Windows бота не теряет: автозапуск поднимет его снова, база на диске.
- Бот не требует открытых портов и проброса — он сам ходит в Telegram по HTTPS.

## 9. Мини-приложение (`/app`) на ПК

Кнопка «Открыть дневник» внутри Telegram требует **HTTPS-адрес, доступный из интернета**:
Telegram не пускает `http://127.0.0.1` и не умеет ходить на серые домашние IP. Сам бот от
этого не зависит — он ходит в Telegram исходящими запросами, ему адрес не нужен.

### 9.1 Посмотреть интерфейс в браузере (без Telegram, минута)

Двойной клик по **`start-web.bat`** → открой <http://127.0.0.1:8080>.

Нужен демо-режим (вход без подписи Telegram) — запусти вручную:

```powershell
cd C:\kkal
python server.py --demo --port 8099
```

→ <http://127.0.0.1:8099>. Данные берутся из той же `data\kkal.db`, подпись Telegram не
проверяется, поэтому страница открывается в обычном браузере.

Это **ещё не** мини-приложение в Telegram: клиент по такому адресу ничего не откроет.
Зато видно вёрстку, графики и записи — удобно для правок.

### 9.2 Открыть внутри Telegram через бесплатный туннель (без VDS и оплаты)

Порядок важен: Telegram читает адрес из `config.json` в момент старта бота.

1. **Поставь cloudflared** (один `.exe`, регистрация не нужна):

   ```powershell
   winget install --id Cloudflare.cloudflared -e
   ```

   Либо вручную: <https://github.com/cloudflare/cloudflared/releases> →
   `cloudflared-windows-amd64.exe`, переименовать в `cloudflared.exe`, положить в папку проекта.

2. **Запусти веб-сервер**: двойной клик по `start-web.bat` (порт 8080). Окно не закрывай.

3. **Запусти туннель** — второе окно PowerShell, из папки проекта:

   ```powershell
   .\cloudflared.exe tunnel --url http://127.0.0.1:8080
   ```

   Через несколько секунд в окне появится адрес вида
   `https://sturdy-porpoise-abc.trycloudflare.com`. Это публичный HTTPS-адрес твоего
   дневника: всё, что придёт на него, уходит на твой ПК.

4. **Впиши адрес в `config.json`** — рядом с токеном:

   ```json
   {
     "token": "123456789:AAH...",
     "owner_id": 123456789,
     "utc_offset": 4,
     "db": "data/kkal.db",
     "webapp": {
       "url": "https://sturdy-porpoise-abc.trycloudflare.com"
     }
   }
   ```

   Строго `https://`, без слэша в конце и без `/index.html`. Адрес с другой схемой бот
   отбросит и напишет предупреждение в лог.

5. **Перезапусти бота** (закрой окно бота, снова `start-bot.bat`). При старте бот заново
   регистрирует команды и ставит кнопку меню — только теперь Telegram узнаёт про дневник.

6. В Telegram: `/app` или кнопка слева от поля ввода. Откроется дневник.

Что важно помнить:

- адрес `trycloudflare.com` **меняется при каждом запуске туннеля** — остановил окно,
  ссылка умерла. Тогда повторяй шаги 3–5 (заново вписать адрес и перезапустить бота);
- мини-приложение доступно ровно пока живут окно туннеля и сам ПК; бот при этом продолжает
  работать, даже если туннель закрыт;
- ПК уснул/выключился — мини-приложение не открывается, `/app` в боте об этом не догадывается;
- бесплатный quick tunnel не обещает скорость и может быть заблокирован в РФ — это нормально;
  альтернатива без туннеля: постоянный домен + VDS с Caddy (см. `deploy/`), но это деньги;
- если очень нужен неизменный адрес на домашнем ПК — именованный туннель Cloudflare
  (`cloudflared tunnel create`) со своим доменом, тоже бесплатно, но нужен домен.

### 9.3 Убрать кнопку, если мини-приложение не нужно

@BotFather → `/setmenubutton` → выбрать бота → удалить кнопку. Или просто оставь
`webapp.url` пустым: бот перестанет предлагать `/app`, но уже поставленную кнопку
Telegram сам не снимет — её надо убрать через BotFather.

Обратная сторона: при живом `webapp.url`, но выключенном `start-web.bat`, кнопка
открывает пустоту — Telegram покажет «не удалось открыть».

## 10. Обновления

```powershell
cd C:\kkal            # твоя папка проекта
git pull
```

Затем перезапусти бота (Планировщик → «Завершить» → «Выполнить»). Твои данные не
затрагиваются: `data/` в репозиторий не попадает и `git pull` её не трогает.

Если `git pull` ругается на изменённые файлы — значит ты правил код сам: `git stash` →
`git pull` → `git stash pop`. `config.json` и `data/` тут не при чём, они вне git.

## 11. Резервная копия

База — один файл: `C:\kkal\data\kkal.db` (плюс `kkal.db-wal` и `kkal.db-shm`, если есть).

```powershell
# бот должен быть остановлен, иначе копия может быть неполной
$dst = "C:\Backup\kkal-$(Get-Date -Format yyyy-MM-dd)"
New-Item -ItemType Directory $dst -Force | Out-Null
Copy-Item C:\kkal\data\kkal.db* $dst      # база вместе с -wal и -shm
```

Быстрая выгрузка без остановки бота — команда `/export` в Telegram: бот пришлёт CSV.

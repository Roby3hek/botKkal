# Дневник КБЖУ — Telegram-бот + мини-приложение

Личный помощник по питанию: база своих блюд с КБЖУ на 100 г, запись съеденного в граммах,
итоги дня, статистика за 7/30 дней и за всё время, отметки тренировок, выгрузка в CSV —
в чате с ботом и в мини-приложении с графиками внутри Telegram.

Работает на чистом Python — **без зависимостей**, без платных сервисов.
База — один файл SQLite. ИИ (фото еды, разбор текста, недельный коуч) — необязательная
надстройка: можно вообще без него, можно на бесплатной локальной модели.

## Что умеет

### В чате

| Экран | Что делает |
|---|---|
| ➕ Записать еду | выбрать блюдо из базы или ввести разово, указать граммы |
| 📊 Сегодня | прогресс-бары по ккал/Б/Ж/У, список приёмов пищи, тренировка |
| 🍱 Мои блюда | база блюд постранично, поиск, удаление |
| 🏋️ Тренировка | пометить день «была / не было» + заметка |
| 📈 Статистика | 7 дней, 30 дней, всё время; средние, коридор ±10% от цели, тренировки против отдыха |
| ⚙️ Цели | ккал и БЖУ на день |
| 📱 Мини-приложение | кнопка «Открыть дневник» под сообщением и в меню чата |
| 📷 Фото еды | прислал фото тарелки в чат — бот показал позиции с граммами и ккал, запись одним нажатием (нужна включённая нейросеть) |

Команды: `/start` `/app` `/eat` `/add` `/today` `/dishes` `/workout` `/stats` `/goal` `/undo` `/export` `/id` `/help` `/cancel`.

Мелочи, которые важны в быту:

- `/eat сырники 150` — записать одной строкой, без кнопок;
- `/add Сырники 220 18 9 24` — добавить блюдо одной строкой;
- поиск прощает раскладку и порядок слов: «гречка» найдёт «Гречка отварная»;
- `/undo` удаляет последнюю запись за сегодня;
- `/export` присылает CSV (Excel открывает сразу, разделитель `;`, UTF-8 с BOM).

### В мини-приложении

Тот же дневник, но экраном и с графиками:

- **Сегодня** — кольцо калорий, полоски Б/Ж/У, приёмы пищи по времени,
  быстрые кнопки недавних блюд, «повторить вчерашнее»;
- **Поиск и запись** — поиск по базе с учётом раскладки, ввод граммов,
  разовая запись без блюда в базе, добавление нового блюда на лету;
- **Блюда** — весь список, правка КБЖУ, удаление;
- **Статистика** — 7/30 дней и всё время, график по дням, средние, тренировки против отдыха;
- **Тренировка и цели** — отметка дня, заметка, ккал и БЖУ на день;
- **ИИ** (если включён) — фото еды, разбор фразы «съел 200 г гречки и курицу», недельный разбор.

Мини-приложение — это `webapp/`: три файла (`index.html`, `app.css`, `app.js`) без сборки
и без фреймворков. Тема (светлая/тёмная) берётся из Telegram, кнопки «Назад» и
«Готово» — нативные.

## Мини-приложение: как включить

Нужен **https-адрес**: Telegram не открывает мини-приложения по http, кроме `localhost`
во время разработки. Вариантов два: свой домен и VDS (шаги ниже) либо домашний ПК
с бесплатным туннелем — см. [docs/windows.md §9](docs/windows.md).

> **Без VDS и без оплаты.** `start-web.bat` поднимает сервер на ПК,
> `cloudflared tunnel --url http://127.0.0.1:8080` выдаёт публичный `https://…` адрес,
> его вписываешь в `webapp.url`, перезапускаешь бота — `/app` открывается. Цена: адрес
> туннеля меняется при каждом запуске, а ПК должен быть включён.

1. **Домен.** Купи или поддомень свой (например `kkal.твойдомен.ru`) и направь A-запись
   на IP сервера. Сертификат Let's Encrypt Caddy получит сам, бесплатно.

2. **Запусти сервер локально и посмотри глазами** (можно без домена):

   ```powershell
   python server.py --demo --port 8080
   ```

   Открой `http://127.0.0.1:8080` — откроется тот же экран с демо-данными.
   `--demo` разрешает вход без Telegram; **на сервере так не оставляй**.

3. **Выложи на VDS** (Debian/Ubuntu, путь `/opt/kkal`):

   ```bash
   sudo useradd --system --home /opt/kkal --shell /usr/sbin/nologin kkal
   sudo mkdir -p /opt/kkal && sudo chown kkal:kkal /opt/kkal
   # скопируй проект в /opt/kkal (scp/rsync/git), затем:
   sudo -u kkal mkdir -p /opt/kkal/data
   sudo cp deploy/kkal.service deploy/kkal-web.service /etc/systemd/system/
   sudo cp deploy/Caddyfile /etc/caddy/Caddyfile   # замени домен на свой
   sudo systemctl daemon-reload
   sudo systemctl enable --now kkal kkal-web caddy
   ```

   Python 3.9+ из системы, ставить ничего не надо — зависимостей нет.

4. **Впиши адрес в `config.json`** на сервере и перезапусти оба сервиса:

   ```json
   "webapp": { "url": "https://kkal.твойдомен.ru" }
   ```

   ```bash
   sudo systemctl restart kkal kkal-web
   ```

   Бот при старте сам поставит кнопку меню чата на этот адрес; отдельно можно
   одной командой: `python server.py --register`.

5. **Проверь в Telegram:** команда `/app` → кнопка «Открыть дневник».
   Если кнопка не появилась — смотри `journalctl -u kkal -n 50`
   (Telegram отвергает http-адреса, в логе будет предупреждение).

### Как мини-приложение пускает только тебя

Telegram при открытии передаёт `initData` — строку с подписью бота. Сервер проверяет её
через `HMAC-SHA256` с ключом, производным от токена бота (`kkal/auth.py`), сверяет
`auth_date` (не старше 24 часов) и пускает только владельца. Запросы без подписи получают
`401` — посторонний, узнавший адрес, увидит пустой экран. CORS-заголовки отдаются только
в демо-режиме; в бою — нет.

## Нейросеть (необязательно)

Три вещи, каждая включается одним ключом в конфиге:

1. **Фото еды → КБЖУ.** Два входа, один результат:
   - **в чате** — просто пришли боту фото тарелки: он скачает снимок, разберёт его
     и ответит списком «Сырники — 150 г · 330 ккал…». Ничего не пишется, пока не
     нажмёшь «✅ Записать всё» (есть и «❌ Отмена»). Знакомые блюда берутся из твоей
     базы и пересчитываются по граммам, незнакомые пишутся разово.
   - **в мини-приложении** — то же самое на экране, с правкой граммов перед сохранением.
2. **Свободный текст.** «Съел 200 г гречки и куриную грудку» → позиции. Если блюдо есть
   в твоей базе, калории берутся **из базы**, а не из ответа модели — цифры не уплывают.
3. **Недельный коуч.** Разбор последних 7 дней по твоим же цифрам: что было, где перебор,
   что поправить. Не диета из интернета, а разговор о твоём дневнике.

Всё это необязательно: ручной ввод работает всегда, ИИ просто добавляет кнопки.
Если модель недоступна, бот пишет «Не получилось разобрать…» и остаётся рабочим.

```json
"ai": {
  "enabled": true,
  "base_url": "https://api.openai.com/v1",
  "api_key": "sk-...",
  "model": "gpt-4o-mini",
  "vision_model": "gpt-4o-mini",
  "timeout": 30
}
```

Подходит любой сервис с OpenAI-совместимым `/chat/completions`: OpenAI, OpenRouter,
DeepSeek, Groq, Ollama. Для фото нужна модель, которая умеет смотреть картинки
(`vision_model`), для текста и коуча — обычная (`model`).

**Бесплатный вариант — локальная модель на том же VDS** (нужен запас RAM, фото — от ~7B):

```bash
curl -fsSL https://ollama.com/install.sh | sh
ollama pull llava          # смотрит картинки
ollama pull llama3.2       # текст и коуч
```

```json
"ai": {
  "enabled": true,
  "base_url": "http://127.0.0.1:11434/v1",
  "api_key": "ollama",
  "model": "llama3.2",
  "vision_model": "llava"
}
```

Плюсы: никому не платишь, фото не уходит в интернет. Минусы: на слабом VDS медленно
и точность ниже, чем у больших моделей. Начни с текста и коуча, фото включи, если
хватит ресурсов.

Если модель не настроена, `/api/ai/*` отвечает `503` и приложение прячет кнопки ИИ;
если модель настроена, но не ответила — `502` с текстом ошибки. Ручной ввод работает
в любом случае.

## Запуск бота за 5 минут

1. **Python 3.9+** — проверь: `python --version`.

2. **Получи токен.** В Telegram напиши [@BotFather](https://t.me/BotFather) → `/newbot` →
   придумай имя и username (должен заканчиваться на `bot`). Он даст токен вида
   `123456789:AAH...` — это пароль от бота, никому не показывай.

3. **Кто владелец.** В `owner_id` можно вписать число (например `123456789`) или ник
   строкой (`"@robchik69"` или `"robchik69"`) — поддерживаются оба варианта, ник
   сравнивается без учёта регистра и без `@`.

   Число надёжнее: ник можно сменить и потерять доступ. Свой id бот сам покажет
   командой `/id`, а узнать со стороны можно через [@userinfobot](https://t.me/userinfobot).

4. **Конфиг.** В папке проекта:

   ```powershell
   Copy-Item config.example.json config.json
   ```

   Открой `config.json` и вставь токен и владельца:

   ```json
   {
     "token": "123456789:AAH...",
     "owner_id": 123456789,
     "utc_offset": 4,
     "db": "data/kkal.db"
   }
   ```

   `utc_offset` — часовой пояс от UTC: Саратов = `4`, Москва = `3`, Екатеринбург = `5`.

5. **Создай базу.** Схема поднимется сама при первом запуске — ничего делать не надо.

6. **Запусти:**

   ```powershell
   python bot.py
   ```

   В консоли будет `Бот @твой_бот запущен`. Открой его в Telegram, отправь `/start` — готово.
   Остановить: `Ctrl+C`.

## Как хранятся данные

- Блюдо хранится **на 100 г**: `Сырники — 220 ккал, Б18 Ж9 У24`.
  Записал 150 г → бот сам посчитает 330 ккал.
- Разовая еда (без блюда в базе) пишется сразу в ккал, тоже с итогами за день.
- Всё лежит в `data/kkal.db`. **Бэкап = скопировать файл** (и `-wal`, `-shm`, если есть).
  Плюс всегда есть `/export` в CSV.
- Бот и сервер мини-приложения работают с одной и той же базой (SQLite в режиме WAL,
  транзакции короткие) — можно записать в чате и увидеть в приложении.

## Автозапуск

**Windows.** Подробная пошаговая инструкция — [docs/windows.md](docs/windows.md):
перенос проекта из OneDrive, запуск двойным кликом по `start-bot.bat`, автозапуск
через Планировщик заданий без окна консоли, разбор ошибок, бэкап. Коротко: задача
«При входе в систему» → программа `pythonw.exe`, аргументы `bot.py`, рабочая папка —
папка проекта.

**Linux (VDS).** Готовые юниты в `deploy/`: `kkal.service` (бот) и `kkal-web.service`
(сервер приложения). Ставятся как в разделе про мини-приложение.

Важно: **не запускай два экземпляра бота одновременно** — Telegram отдаст одному
и второй упадёт с ошибкой `409 Conflict`. Бот сам переживает обрыв сети и перезапуск:
позиция в очереди сообщений хранится в базе, ничего не теряется и не дублируется.

## Проверка без Telegram

```powershell
python selftest.py        # 91 проверка бота на поддельном API
python selftest_web.py    # 88 проверок API и HTTP мини-приложения
python demo.py            # печатает в консоль, как выглядят экраны бота
```

Все три скрипта не ходят в сеть и не трогают `data/kkal.db` — работают во временной папке
`data/_selftest*`. `selftest_web.py` поднимает настоящий HTTP-сервер на
`127.0.0.1:0` и проверяет статику, JSON-API, подпись `initData`, `401` на битой подписи,
CSV и заголовки.

```

demo.py               демонстрация экранов в консоли
start-bot.bat         запуск бота на Windows двойным кликом
start-web.bat         запуск веб-сервера мини-приложения на Windows двойным кликом
selftest.py           автотест бота
selftest_web.py       автотест API мини-приложения и HTTP
config.example.json   шаблон конфига (webapp + ai)
webapp/               мини-приложение: index.html, app.css, app.js
deploy/               systemd-юниты и Caddyfile для VDS
docs/windows.md       инструкция: запуск на своём ПК вместо сервера
kkal/api.py           Telegram Bot API на urllib
kkal/db.py            SQLite: блюда, приёмы пищи, дни, цели, настройки
kkal/fmt.py           числа, даты, прогресс-бары, экранирование HTML
kkal/handlers.py      вся логика бота: команды, кнопки, диалоги, отчёты
kkal/webapi.py        JSON-API мини-приложения
kkal/auth.py          проверка подписи initData
kkal/ai.py            необязательный ИИ: фото, текст, недельный коуч

```

## Если что-то не так

- `409 Conflict` в логе — этим токеном уже пользуется другой запущенный экземпляр.
  Закрой второй (или перезагрузи ПК), пауза и повтор у бота уже встроены.
- Бот отвечает «🔒 Это личный бот одного человека» — `owner_id` не совпал.
  Отправь `/id`, возьми оттуда число и впиши в конфиг.
- `/app` пишет «Мини-приложение пока не настроено» — в `config.json` нет `webapp.url`.
- Кнопка «Открыть дневник» не появляется — адрес должен быть **https**; смотри
  `journalctl -u kkal -n 50`, бот пишет предупреждение про http.
- Мини-приложение показывает «initData устарел, переоткрой мини-апп» — поверь часы
  на сервере (`timedatectl`): подпись живёт 24 часа и сверяется с `auth_date`.
- Мини-приложение отвечает `401` — открыто не из Telegram (или токен в конфиге сервера
  не тот, что у бота: подпись считается именно от токена).
- `ValueError: invalid literal for int()` — старая версия `bot.py` требовала только число.
  Сейчас `owner_id` принимает и `"@username"`.
- На фото бот отвечает «нейросеть выключена» — в `config.json` секция `ai` выключена или
  нет `api_key` (для локальной Ollama ключ не нужен, достаточно `http://127.0.0.1:11434/v1`).
- На фото бот отвечает «Не получилось разобрать» — модель недоступна или не умеет смотреть
  картинки: в `vision_model` нужна vision-модель (`gpt-4o-mini`, `llava`), а не текстовая.
- Ничего не приходит после запуска — проверь, что не запущен второй экземпляр,
  и посмотри `data/bot.log`.

## Дальше

- Свободный текст прямо в чате: «съел 200 г гречки и курицу» → те же позиции с подтверждением.
- Голосовой ввод: «запиши обед» — расшифровка на сервере, без платных API.
- Напоминания: пуш в чат, если день не закрыт к вечеру.
- Шаблоны приёмов пищи: «мой обычный завтрак» одним нажатием.
